# Glossary

| Term | Meaning | Chatwoot equivalent |
|---|---|---|
| **Organization** | The tenant. Billing, security and membership boundary. Every tenant row carries `organization_id` | `accounts` |
| **Workspace** | Operational unit inside an organization (e.g. a brand or region). Owns inboxes, contacts, conversations | — (new) |
| **Membership** | A user's link to an organization with a role | `account_users` |
| **Inbox** | One connected channel instance: one website, one Facebook Page, one Instagram account, one WhatsApp number | `inboxes` |
| **Channel connection** | Credentials and status for an inbox's provider | `channel_*` tables |
| **Channel route** | Global lookup `(provider, external_id) → tenant + inbox` used by webhook ingress | URL param / payload lookups |
| **Adapter** | Python class implementing `BaseChannelAdapter` for one provider | `*::SendOn*Service` + `*EventsJob` |
| **Contact** | A customer person, scoped to a workspace | `contacts` |
| **Contact identity** | A contact's address on one inbox (`source_id` = PSID, IGSID, wa_id, visitor id) | `contact_inboxes` |
| **PSID** | Page-Scoped ID: a Messenger user's id for one Facebook Page | — |
| **IGSID** | Instagram-Scoped ID: an Instagram user's id for one business account | — |
| **wa_id / BSUID** | WhatsApp user id (phone-based) / Business-Scoped User ID (newer, phone-independent) | — |
| **WABA** | WhatsApp Business Account: owns phone numbers and message templates | — |
| **Conversation** | Thread between one contact identity and an inbox, with status and assignee | `conversations` |
| **Display number** | Human-friendly per-workspace conversation number (#1042) | `display_id` |
| **Message direction** | `incoming` (customer), `outgoing` (agent/AI/automation), `activity` (system note in timeline), `template` | `message_type` |
| **Private note** | Outgoing message with `is_private = true`, never sent to the channel | `messages.private` |
| **External id** | Provider's id for a message (`wamid…`, Messenger `mid…`) | `messages.source_id` |
| **Client message id** | Id generated by our client before sending, for idempotent retries | `echo_id` (widget) |
| **24-hour window** | Meta rule: free-form replies are allowed for 24 h after the customer's last message; afterwards WhatsApp needs a template and Messenger needs a message tag | — |
| **Outbox** | `event_outbox` table: domain events written in the same transaction as the change, relayed to workers | Wisper dispatch in `after_commit` |
| **Inbound event** | Raw provider webhook stored in `inbound_webhook_events` before processing | — |
| **Ordering key** | Value (usually conversation or contact identity) that forces related tasks to run one at a time | Redis mutex keys |
| **AI agent** | Tenant-configured assistant (provider, model, prompt, tools, knowledge bases) | Captain assistant |
| **AI session** | Per-conversation AI memory: summary, facts, LangGraph thread id | — |
| **AI run** | One execution of the graph in response to one customer message | — |
| **Handoff** | AI stops responding and a human takes over the conversation | `bot_handoff!` |
| **RAG** | Retrieval-Augmented Generation: fetch relevant knowledge chunks and give them to the model | Captain document search |
| **RLS** | PostgreSQL row-level security: the database filters rows by `organization_id` | — |
| **Tenant context** | `organization_id`, `workspace_id`, user and permissions resolved for a request or task | `Current.account`, `Current.account_user` |
