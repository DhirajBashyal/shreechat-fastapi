# API Design

REST over HTTPS, JSON bodies, OpenAPI 3.1 generated by FastAPI at `/api/openapi.json` (internal routes hidden from the public spec).

## 1. Conventions

| Topic | Rule |
|---|---|
| Base path | `/api/v1` |
| Tenant scoping | Organization-level resources: `/api/v1/organizations/{organization_id}/…`. Workspace resources: `/api/v1/workspaces/{workspace_id}/…` (the workspace determines the organization) |
| Auth header | `Authorization: Bearer <access JWT or API token>` |
| IDs | UUID strings. Conversations can also be addressed by number: `/conversations/by-number/{display_number}` |
| Timestamps | ISO 8601 UTC with milliseconds (`2026-11-08T10:15:02.412Z`) |
| Pagination | Cursor based: `?limit=25&cursor=<opaque>` → `{"data": [...], "next_cursor": "…" \| null}`. `limit` ≤ 100 |
| Filtering | Query params for simple filters; `POST …/search` with a JSON filter body for complex ones |
| Partial updates | `PATCH` with only the fields to change. `null` clears a nullable field; omitted fields are unchanged |
| Idempotency | `Idempotency-Key` header supported on all `POST` creating resources (stored 24 h in `idempotency_keys`). Messages also accept `client_message_id` |
| Concurrency | Resources with an `updated_at` return `ETag`; `If-Match` makes updates conditional (`412` on mismatch). Optional for clients |
| Rate limits | Headers `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset`; `429` with `Retry-After` |
| Versioning | Breaking changes → `/api/v2`. Additive changes (new fields/endpoints) within v1 |

### Error format

```json
{
  "error": {
    "code": "validation_error",
    "message": "Request validation failed",
    "details": [{ "field": "content", "issue": "must not be empty" }],
    "request_id": "req_01JC8Z4X7S3QK2"
  }
}
```

| HTTP | `code` examples | When |
|---|---|---|
| 400 | `bad_request` | Malformed JSON, invalid cursor |
| 401 | `unauthenticated`, `token_expired`, `session_revoked`, `mfa_required` | Missing/invalid credentials |
| 402 | `plan_limit_reached`, `feature_not_in_plan` | Plan limits |
| 403 | `permission_denied`, `organization_suspended`, `api_access_disabled` | Authenticated but not allowed |
| 404 | `not_found` | Missing **or not visible** (cross-tenant ids always 404) |
| 409 | `conflict`, `channel_already_connected`, `duplicate` | Uniqueness/state conflicts |
| 412 | `precondition_failed` | `If-Match` mismatch |
| 413 | `payload_too_large` | Body/file too large |
| 415 | `unsupported_media_type` | Upload type not allowed |
| 422 | `validation_error`, `invalid_transition`, `window_closed` | Semantically invalid |
| 429 | `rate_limited` | Throttled |
| 500 | `internal_error` | Bug (details only in logs) |
| 503 | `unavailable` | Dependency down / maintenance |

**Permissions column below:** a permission code from [../10_AUTHENTICATION_AND_RBAC.md](../10_AUTHENTICATION_AND_RBAC.md#42-permission-codes); "member" = any member of the organization/workspace; "visible" = the conversation passes the visibility filter. **Tenant column:** `O` = caller must be a member of the organization in the path or owning the resource; `W` = caller must have access to the workspace in the path; `—` = not tenant-scoped.

Delivered request format:

```http
POST https://customer.example/hooks/converse
Content-Type: application/json
User-Agent: Converse-Webhooks/1
X-Converse-Event: message.created
X-Converse-Delivery: 7c1d2e3f-...          (stable across retries → receivers dedupe on it)
X-Converse-Timestamp: 1762597004
X-Converse-Signature: sha256=<hex HMAC_SHA256(secret, "<timestamp>.<raw body>")>

{ "event": "message.created", "occurred_at": "2026-11-08T10:16:44.120Z", "workspace_id": "…",
  "data": { "message": { … }, "conversation": { "id": "…", "display_number": 1, "status": "open" }, "contact": { … } } }
```

Same signing scheme as Chatwoot (`X-Chatwoot-Signature: sha256=HMAC(secret, "<ts>.<body>")`), with different header names. Receivers should reject timestamps older than 5 minutes.
